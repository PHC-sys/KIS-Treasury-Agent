# KTB 데이터 수집 시스템 — Phase 0 사양서

> **목표**: 차장님이 지정한 데이터를 수집하고, **매일 최신으로 자동 업데이트**하는 시스템.
> **최우선**: 한 번 만들고 나면 `python update.py` 한 번(또는 스케줄러)으로 항상 최신이 되는 것.
> **범위**: 이 문서는 데이터 수집 레이어만 다룬다. 에이전트·스코어링은 별도(ktb-agent-design.md).
> **기한**: 하루. 완벽보다 **돌아가고 매일 갱신되는 것**이 우선.

---

## 0. 제일 중요한 원칙 — "업데이트 가능"이 전부

이 시스템의 성공 기준은 데이터 종류 개수가 아니라 **재실행 안전성(idempotent)**이다.

- `update.py`를 몇 번을 돌려도 결과가 같아야 한다(중복 적재 없음).
- 매 실행은 **마지막 수집일 다음날부터 오늘까지**만 증분 수집한다(전체 재수집 아님).
- 값의 저장 키는 `(날짜, 필드)` — 같은 키면 덮어쓰기(upsert).
- 최초 1회만 과거 2년 백필, 이후엔 자동 증분.

이 원칙만 지켜지면 나머지는 수집기를 하나씩 붙이는 반복 작업일 뿐이다.

## 1. 아키텍처 — 3층

차장님 스키마(ktb_daily 42컬럼)는 **최종 분석 테이블(wide)**이다. 그 밑에 수집 원장을 깐다.

```
raw/                       원본 응답 그대로 보관 (재구성용, 절대 수정 안 함)
  krx_futures_YYYYMMDD.csv
  krx_investor_YYYYMMDD.csv
  ecos_YYYYMMDD.csv  ...

db/ktb.sqlite  →  ledger 테이블 (long format, 값 + 메타)
  (date, field, value, source, as_of, fetched_at)  PK=(date, field)

out/ktb_daily.csv  →  차장님 42컬럼 wide 테이블 (ledger에서 생성)
```

왜 원장을 따로 두나: 어떤 값이 **언제 어느 소스에서** 들어왔는지 남겨야 조용한 오염(옛날 값이 그대로 재반환되는 것)을 잡을 수 있다. wide 테이블만 있으면 이걸 못 잡는다.

### ledger 스키마
```sql
CREATE TABLE ledger (
  date       TEXT NOT NULL,   -- 'YYYY-MM-DD' 데이터 기준 영업일
  field      TEXT NOT NULL,   -- ktb_daily 컬럼명 (ktb3_settle 등)
  value      REAL,            -- 결측이면 행 자체를 안 만든다(빈칸=행 없음)
  source     TEXT NOT NULL,   -- 'krx' | 'ecos' | 'fred' | 'kofr' | 'fx' | 'manual'
  as_of      TEXT NOT NULL,   -- 소스가 밝힌 데이터 기준일
  fetched_at TEXT NOT NULL,   -- 인출 시각 (ISO8601)
  PRIMARY KEY (date, field)
);
```

**출력 규칙 (차장님 지정 — 반드시 준수):**
- 결측 = **빈칸** (0 금지). ledger에 행이 없으면 CSV 셀은 빈칸.

- 컬럼 순서 고정, 2행 헤더 유지 형식은 차장님 템플릿 따름.
- `note`는 수집기가 비워둠(사람이 나중에).

## 3. 소스별 수집 담당 — 무엇이 자동이고 무엇이 수동인가

### 자동 (무료, 하루 안에 구축) — collectors/

| 파일 | 소스 | 채우는 컬럼 |
|---|---|---|
| `krx.py` | KRX 정보데이터시스템 | ktb3/10_settle·chg·vol·oi, OHLC(open/high/low), fx/bank/itrust/ins_net_ktb3·ktb10, y_ktb3/10/30, ktb3/10_theo_basis, days_to_expiry, roll_flag |
| `ecos.py` | 한국은행 ECOS API | base_rate, cd91 |
| `kofr.py` | kofr.kr (또는 ECOS) | kofr |
| `fred.py` | FRED | ust10 (DGS10) |
| `fx.py` | ECOS(또는 smbs.biz) | usdkrw |

`fx_cum_ktb3/10`은 수집이 아니라 **파이프라인이 fx_net 누적합으로 계산**(update.py에서).

### 수동 / 나중 (무료 소스 없음 → 사내단말=인포맥스)

| 컬럼 | 사유 |
|---|---|
| irs3y, irs10y, ois3y, kr_cds5 | 무료 소스 없음. 인포맥스 엑셀에서 뽑아 `manual_input.csv`로 병합 |

→ **이 4개는 하루 목표에서 빠져도 됨.** 빈칸으로 두고, `manual_input.csv`(date, field, value) 경로만 만들어 두면 나중에 인포맥스 값 붙여넣기로 채운다. update.py가 이 파일을 source='manual'로 병합.

### KRX 구현 지침 (Claude Code가 조사 후 결정)
- **1순위 시도: `pykrx` 라이브러리.** 국고금리·채권은 커버 가능성 높음. 단 **파생(선물) 투자자별 수급·OI를 pykrx가 커버하는지 불확실** → 반드시 먼저 확인.
- **pykrx가 파생을 못 하면**: KRX 정보데이터시스템 JSON 엔드포인트 직접 호출.
  `data.krx.co.kr/comm/bldAttendant/getJsonData.cmd` (bld 파라미터 + OTP 흐름). 화면별 bld 코드는 브라우저 네트워크 탭에서 확인 필요.
- **오픈API(openapi.krx.co.kr)**: 인증키 필요. 회사에서 키 반출 가능하면 이게 가장 안정적 → 키 발급 방법을 먼저 정리해 사용자에게 요청.
- 개별종목 시세는 만기교체일에 점프(롤)가 있으니, 만기정보로 roll_flag를 반드시 산출.

## 4. update.py — 오케스트레이터 (이 파일이 시스템의 심장)

```
1. 대상 기간 결정
   - 각 소스별 ledger 최종 date 조회 → 그 다음 영업일부터 오늘까지
   - ledger 비어있으면(최초 실행) → 오늘부터 2년 전까지 백필
2. 각 collector 실행 → [(date, field, value, as_of), ...] 반환
3. 행마다 sanity check (§5) → 통과분만
4. raw 원본을 raw/ 에 타임스탬프 파일로 저장
5. ledger에 upsert (date,field 충돌 시 덮어쓰기)
6. 파생 계산: fx_cum_ktb3/10 = fx_net 전체 이력 누적합 → ledger에 갱신
7. out/ktb_daily.csv 재생성 (거래일만, 42컬럼 고정순, 결측=빈칸)
8. 건강 리포트 출력 (아래)
```

**건강 리포트(매 실행 끝에 콘솔+로그):**
```
=== UPDATE 2026-07-28 14:03 ===
krx    : 최종 2026-07-25 → +2행 (7/28 데이터 아직 미공표)  OK
ecos   : 최종 2026-07-25 → +2행  OK
fred   : 최종 2026-07-25 → +1행  OK
kofr   : 최종 2026-07-25 → +2행  OK
fx     : 최종 2026-07-25 → +2행  OK
manual : irs3y/irs10y/ois3y/kr_cds5 최종 2026-07-20 (5일 지연)  ⚠
[SANITY] 통과 118 / 실패 0
[EXPORT] out/ktb_daily.csv  512행
```

**멱등성 테스트(필수)**: update.py를 연속 2번 돌려서 2번째가 "+0행"이고 CSV가 바이트 단위로 동일하면 통과.

## 5. Sanity Check — 조용한 오염 방지 (적재 전 필수)

하나라도 실패하면 그 행은 **적재 중단 + 로그에 명시**. 조용히 넘어가지 않는다.

- **영업일 일치**: as_of가 주말/공휴일이 아니고, 기대한 거래일과 맞는가.
- **동결 감지**: settle·yield·usdkrw 등 변동 시리즈가 **전일과 완전히 동일한 값**이면 의심 → 플래그(세션 끊겨 옛 값 재반환 가능성).
- **물리적 범위**: 전일 대비 변화가 상식 범위인가.
  예) KTB3 settle 일변화 |Δ| < 1.0포인트, KTB10 |Δ| < 2.0포인트, 금리 |Δ| < 50bp, usdkrw |Δ| < 5%. (초기 느슨하게, 오탐 나면 조정)
- **부호·형식**: vol·oi ≥ 0 정수, 금리 > 0, 결측은 0이 아니라 빈칸.

sanity 실패는 에러가 아니라 **경고+격리**: 해당 (date,field)만 건너뛰고 나머지는 진행, 리포트에 남긴다.

## 6. 스케줄링 (매일 자동 갱신)

- 국내 확정치는 장 마감 후 나오므로 **평일 18:00** 실행 권장. 주말/공휴일은 collector가 알아서 "신규 없음"으로 끝남(멱등).
- Windows 작업 스케줄러:
  ```
  schtasks /create /tn "KTB_Update" /tr "python C:\ktb-agent\update.py" /sc daily /st 18:00
  ```
- 실패/지연은 건강 리포트로 드러남. 텔레그램 알림은 이번 범위 밖(다음 단계).

## 7. 이번 하루의 완료 정의 (Definition of Done)

1. `update.py` 실행 → KRX+ECOS+FRED+KOFR+FX에서 **최근치까지** 수집돼 ledger 적재.
2. 최초 실행 시 과거 2년 백필 동작.
3. `out/ktb_daily.csv`가 차장님 42컬럼 스키마·순서·결측규칙대로 생성.
4. update.py 2회 연속 실행 → 2번째 "+0행", CSV 동일(멱등성 통과).
5. `manual_input.csv` 병합 경로 존재(irs/ois/cds용, 비어 있어도 됨).
6. 건강 리포트가 소스별 최종일·신규행수·sanity 결과를 출력.

**하루 목표에서 빼도 되는 것**: 인포맥스 자동화, 텍스트/뉴스, 옵션 IV, 4순위 항목, 텔레그램. 전부 다음 단계.

## 8. 구현 순서 (Claude Code 세션)

```
1. db 스키마 + update.py 뼈대(멱등 upsert·export·건강리포트) — 데이터 없어도 도는 골격
2. collectors/krx.py — 선물 시세·OHLC·OI·거래량 먼저 (가장 크고 중요)
3. krx.py 확장 — 투자자별 수급, 국고금리, 베이시스, 만기정보/roll_flag
4. ecos.py, fred.py, fx.py, kofr.py — 나머지 무료 소스
5. manual_input.csv 병합 경로
6. 멱등성·백필 검증
```
2번에서 KRX가 막히면 나머지 무료 소스(4번)를 먼저 붙여 파이프라인을 살려두고 KRX를 뒤에 해결해도 된다 — 골격(1번)이 먼저 서 있으면 순서는 유연.
