# 개발 인수인계 (다음 세션 / 다음 Claude용)

> 이 문서 하나로 이 프로젝트를 이어받을 수 있게 쓴 것. **먼저 이걸 읽고 시작.**
> 코드 상세는 `src/`, 컬럼 의미는 [데이터_사전.md](데이터_사전.md), 원설계는 [데이터수집_사양.md](데이터수집_사양.md).

---

## 1. 이 프로젝트가 뭔가
한국 국채선물(KTB 3년·10년) **트레이딩 에이전트**를 만드는 프로젝트.
- **Phase 0 (완료)**: 일별 **63컬럼** 데이터(`ktb_daily`)를 수집·검증·적재 → Supabase. 1999~현재 약 6,600 거래일.
- **Phase 2 (진행 중)**: 에이전트. **하이브리드 구조** = Layer 1(일별 두뇌: 방향·포지션) → Layer 2(분봉 실행: 진입·청산 타이밍).

## 2. 데이터 파이프라인 (매일)
사용자가 아침에 **인포맥스 로그인 → `run.bat` 더블클릭**. 내부:
```
[1/4] infomax_pull.refresh_all()  인포맥스 엑셀(infomax_data.xlsx) COM으로 새로고침
[2/4] infomax_pull.load()         엑셀 → ledger(sqlite) 적재
[3/4] update.main()               ECOS·FRED·FX 수집 + 파생계산 + CSV export + 건강리포트
[4/4] push_supabase.main()        out/ktb_daily.csv → Supabase(ktb_daily) upsert
```
원본 진실 = 로컬 `db/ktb.sqlite`(long ledger). wide `out/ktb_daily.csv`는 소비용. Supabase는 클라우드 미러(차장님 read-only).

  update.py           공개소스 수집→sanity→upsert→파생(recompute_derived)→export→리포트

## 4. ★ 인포맥스 IMDH 완전 가이드 (핵심)
인포맥스 데이터는 전부 Excel 애드인 함수 **IMDH**로 가져온다. API 아님.

### 함수 시그니처
```
=IMDH(구분, 종목코드, 조회항목범위, 시작일, 종료일, 조회건수, "옵션")
```
- **구분**: `STK`(국내주식) `IDX`(국내지수) `FUT`(국내선물) `OPT`(옵션) `FX`(외환) `IR`(금리) `BND`(채권) `ECO`(경제지표) `FRN`(해외지수) `FND`(펀드)
- **조회항목범위**: 헤더 셀 범위(예 `A3:B3`). 첫 칸=`일자`, 나머지=항목 텍스트.
- **조회건수**: 최대 **99999**. 길이가 넘으면 시작/종료일 옮겨 여러 번(페이지네이션). 공백 시작=종료일부터 N개.

### 실행 요건 (자동화 함정)
- **32bit Excel + 인포맥스 단말 로그인** 필수(데이터 피드).
- COM 자동화 시 XLL 애드인 수동 등록: `app.RegisterXLL(r"C:\Infomax\bin\excel\imxlexcelai.xll")` — `infomax_pull._register_addin(app)`가 처리.
- **`win32com.Dispatch`** 사용 (NOT `DispatchEx` — DispatchEx는 애드인 안 붙어 `#NAME?`).
- 좀비 Excel 정리: `_kill_headless_excel()` (창 없는 자동화 잔재만 종료, 사용자 Excel 보존).

| 10년 국채연결선물 | FUT | **C67** | (동일) |
| IRS 3년 / 10년 | IR | **IRSTP1KRW03Y** / **IRSTP1KRW10Y** | MID종가 |

- **연결선물**: 분기 월물을 자동 이어붙인 연속 시계열(롤 점프 있음 → `roll_flag`). C65/C67은 [1333] 선물›지수/금리›국채연결선물.
- **순매수**: 기존 4종(외국인합·은행·투신·보험)은 `매수수량 − 매도수량` 차분으로 계산한다.
  ~~인포맥스 '순매수수량' 컬럼은 투신 등 결측 있어 안 씀~~ → **2026-08-15 실측 결과 이 서술은 틀렸다.**
  `X순매수수량`을 직접 받아 기존 4종과 대조하니 **전 구간 완전 일치**(KTB3 6,305일·KTB10 3,889일, 불일치 0).
  그래서 v2.6 신규 4종(증권/개인/연기금/etc)은 **순매수수량을 직접 받는다**. 기존 4종도 전환 가능(미실행 — 항목 23→17로 감소).
- settle는 '현재가'(종가) 사용 — 옛 '약정가/정산가'는 0 결측 많음.

### 옵션 문자열 (build_infomax.py가 조립)
```
Per=일        조회기준: 일(D)·분(MM)·틱(T)·주(W)·월(M)   ← 분봉은 Per=MM
Cycle=5       틱/분 주기 (분봉 5분이면 5)
Bizday=0      데이터 있는 일자만
sort=A|D      A=오름차순
real=false    조회순간 값 아님 (★2026-08-18 실측: real=true와 **과거값 100% 동일**,
              진행 중인 당일 행만 다르다. 즉 '확정치만 준다'는 뜻이 아니다 — 미확정 당일도 온다)
Quote=종가    종가/평균
Close=…       ★틱/분에서: 매수(bid)·매도(ask)·체결·이론가·현물가 선택 가능
Pos=20, Orient=V, DtFmt=1(YYYY-MM-DD), TmFmt=1(hh:mm:ss), unit=true
```
- **분봉 뽑기**: `Per=MM|Cycle=5` → 5분봉. `조회항목`에 시가,고가,저가,현재가,거래량. 히스토리 깊음(1999/2008~) → 초기 1회 페이지네이션(99999/콜, ~수십 콜), 이후 최근분만 증분.
- **호가·현물·이론가**: 틱/분에서 `Close=매수`/`매도`/`현물가`/`이론가` → 장중 스프레드·베이시스 계산 가능.

## 6. 데이터 규율
- **결측=빈칸(NULL)**, 0은 진짜 0. 다운스트림 0으로 채우지 말 것.
- **거래일만**(XKRX 캘린더). 휴장일 행 없음. `TRADING_ANCHOR_FIELDS`(KTB 선물)가 거래일 판정.
- **급변은 살림**: 범위 초과 변동(위기·금리인하·롤갭)은 드롭 아니라 **플래그+적재**(quarantine에 사유 기록).
- 멱등: (date, field) 충돌 시 upsert. 몇 번 돌려도 동일.

## 7. 최근 주요 결정·수정

**2026-09-03 (USDKRW 정규장 OHLC 4컬럼 — 차장님 요청)**
- 신규 **4컬럼**(63→**67**): `usdkrw_open/high/low/close`. 소스 **인포맥스 FX/`USDSP_SMBCC`(정규 09:00~15:30)**.
- 기존 `usdkrw`(ECOS 매매기준율=당일 최초고시, 전일 MAR 기반)는 **그대로 유지** — 이건 시장 OHLC로 별개.
  `close = 현재가`(15:30 마감). 파이프라인이 채권종가(3:30) 후 실행이라 당일 반영됨.
- **★_EXT(연장/야간) 아니라 정규 USDSP_SMBCC.** 파일에 둘 다 있음: `_EXT`=연장(2024 도입, 새벽 2시까지)이라 종가 다름
  (9/3 EXT 현재가 1357.0 vs 정규 1359.3). 우리는 3:30 마감분 = 정규.
- **한국거래라 as-of 시프트 없음**(ust10/wti와 다름). 그래서 `_read_asof` 아니라 **LOAD_SPEC + `_read_one`**(날짜 그대로) 경로.
- 코드: config COLUMNS 67·SOURCE_FIELDS infomax·POSITIVE_FIELDS / sanity `f=="usdkrw"`→`startswith("usdkrw")`(pct비율 OHLC에도) / build_infomax SHEETS `("USDKRW","FX","USDSP_SMBCC",[일자,시가,고가,저가,현재가])` / LOAD_SPEC USDKRW 매핑 / `_read_one` 0-스킵에 `_close` 추가.
- **전이력 백필 완료**(2001-01-02~2026-09-03, 6,329일). 이력 깊이 2001~. Supabase 4컬럼은 다음 run.bat push에서 자동 ADD.

**2026-08-18 (미국채 2Y·10Y OHLC 7컬럼 + as-of/캘린더 버그 2건 — 차장님 요청)**
- 신규 **7컬럼**(56→**63**): `ust10_open/high/low` + `ust2`,`ust2_open/high/low`.
  기존 `ust10`은 이름·값 그대로 두고(=close 역할) OHL만 추가 → 차장님 쪽 도구 안 깨짐.
- **종목코드 규칙(실측)**: `IR` 시장, **만기 2자리 제로패딩** — `US02Y`·`US10Y`·`US20Y`·`US30Y`.
  `US2Y`·`US3Y`·`US5Y`·`US7Y`는 **빈 응답**(1자리는 없음). `TR10Y`·`TR02Y`는 값이 32/37대인 **전혀 다른 종목** — 쓰지 말 것.
- **`GVO:` 접두어 함정**: 단말 [7219] 화면의 `GVO:TR10Y`/`GVO:TR02Y`는 **시장구분이 `FRN`**이다.
  `IR`로 넣으면 빈 응답이라 "IMDH 미지원"으로 오판하기 쉽다. `FRN`의 `현재가` = `IR`의 **`BID_Close`**와 소수점까지 완전 일치(실측).
- **MID 채택**: 기존 ust10 26년치가 `MID_Close`라 시리즈를 통일했다. 단말 화면은 BID이라 MID보다 0.0~0.5bp 높다.
  BID가 필요하면 같은 IR 호출에 `BID_*`가 있으니 **별도 컬럼**으로 추가할 것(기존 시리즈 변경 금지).
- 워크북: `US10Y` 항목 확장 + `US02Y` 신설, 각 **9,000행(1990-08-17~)** 전이력, 에러 0.
  ⚠기존 시트 항목 변경은 `build_infomax.py add`로 안 된다(없는 시트만 추가) → 표적 갱신 스크립트 필요.
- `_read_asof(sheet, {필드: 항목})`로 **다중 항목** 지원하게 일반화. `_read_ust10`·`_read_ust2`·`_read_wti`가 공용.
- 인포맥스 원천 품질: MID OHLC에서 **C가 [L,H] 밖인 날 35일/9,000일(0.4%)**, 최대 0.79bp, 2018년 이후 0건.
  `MID_Low=(BID_Low+ASK_Low)/2`라 bid·ask 최저점 시각이 다르면 발생. **보정하지 않고 원천 그대로 적재**(차장님 지시).

**★버그 A — as-of 동점 시 '오래된' 미국일 채택 (2026-08-18 수정)**
- **증상**: 한국 휴장 연휴로 미국 이틀이 한국 하루에 몰릴 때 **더 오래된 미국 종가**가 최종값이 됐다.
  실측: 한국 2026-03-03 = 미국 02-27(3.942) ← 정답은 03-02(4.035). 05-04·05-06도 동일.
- **원인**: `store.upsert`가 `executemany`라 **나중 실행이 이긴다**. 워크북은 `sort=D`(내림차순)이라
  최신 미국일이 먼저, 오래된 게 나중에 실행돼 덮어썼다.
  폐기된 `fred.py`엔 *"DGS10 CSV는 날짜 오름차순 → 최신 미국일이 마지막에 이겨 upsert"* 주석이 있다.
  **FRED가 오름차순이라 우연히 맞았던 것**이고, 인포맥스로 이관하며 그 전제가 조용히 깨졌다.
- **수정**: `_asof_records`가 한국일별 **`max(미국일)`**로 확정한다(입력 순서 무관). 단위테스트로 오름/내림 양쪽 확인.
- 교훈: **upsert 순서에 의존하는 로직은 입력 정렬이 바뀌면 소리 없이 뒤집힌다.** 순서 비의존으로 짤 것.

**★버그 B — trading_days 전 구간 평일 폴백 (2026-08-18 수정)**
- **증상**: 한국 휴장일 **286일**(2006~2026)을 거래일로 오인. `2026-05-26` ust10 유실(미국 05-22 종가 4.557).
- **원인**: XKRX 캘린더는 **2006-08-18부터**만 제공한다. `sessions_in_range(BACKFILL_START=2000-01-01, …)`가
  `DateOutOfBounds`를 던지는데 `except Exception`이 이를 삼켜 **전 구간이 평일 폴백**이 됐다.
  `exchange_calendars`가 설치돼 있어도 발생 → 설치 여부로는 진단이 안 된다.

**날짜 시프트가 왜 필요한가 (자주 나오는 질문)**
- 인포맥스 일자는 **미국 거래일**이다. 진행 중인 당일 행은 **한국(서버) 날짜**로 찍히기도 한다
  (실측: 한국 토요일 2026-08-15 행에 미국 금요일 08-14 장중값이 담겼고, 확정 후 08-14로 정착).
- 한국 거래일 T에는 **T 직전 미국 영업일 종가**를 넣는다. 미국 종가는 한국시간 새벽 6시 확정이라
  한국 개장 전에 알 수 있다. 당일 미국 행을 그대로 쓰면 한국장 마감 뒤 14시간 더 움직이는 값 = 룩어헤드.
- **미확정 값은 애초에 안 들어온다**: `kdays`가 `ref_date()`까지만 만들어져 진행 중 미국일은 배정 대상이 없다.
  실행 시각 09/15/16/23시 전부 검증 — 원장에 갇힌 미확정 값 0건.
- `real=false`/`real=true`는 **과거값 100% 동일**, 진행 중인 당일만 다르다(10Y 4.743 vs 4.745).

### 8a. 인트라데이(분봉) 수집 — 탐색 완료, 구현 남음 ★현재 여기
**탐색 결과(sandbox/에서 검증)**: 선물·현물 5분봉 모두 **되고, 일별과 정합 확인**.

**분봉 IMDH 레시피** (일별과 옵션은 같고 Per/Cycle만 다름):
```
선물: =IMDH("FUT","C65",[일자,시간,시가,고가,저가,현재가,거래량,미결제약정수량],
            B1,D1,99999,"Per=MM,Cycle=5,sort=D,real=false,...,Pos=20,Orient=V,DtFmt=1,TmFmt=1")
현물: =IMDH("BND","KR1035G00003",[일자,시간,시가,고가,저가,현재가,체결거래량,체결거래대금],
            B1,D1,99999,"Per=분,Cycle=5,real=t,...")   ← 현물은 real=t
```
- **종목**: 선물 C65(3년)/C67(10년) 연결선물. 현물 **지표연속** `KR1035G00002/03/05/10`(2/3/5/10년) — 코드 안 바뀜.
- **항목**: 분봉은 **`시가/고가/저가/현재가`(플레인, 선물과 동일)**. 선물=가격, 현물=**수익률(%)**. `일자`+`시간`(별칼럼) → `ts`.
- **선물엔 미결제약정수량(OI)도 분봉으로 옴**(EOD 아님 — 이전 오판 정정). 현물엔 OI 없음, 대신 체결거래대금.
- **검증**: 07-31 5분봉→일 OHLC·OI가 우리 일별과 **정확 일치**(선물). 현물 5분 고/저=장외일별과 일치, y_ktb3(ECOS)와 일관.

**★ 분봉 gotchas (중요)**:
1. **계산에 시간 걸림 → 충분히 대기/폴링 후 읽기.** 고정 sleep 짧으면 **0봉/0값**(내가 여기서 헤맴). 작동 예: `_archive_discovery/5분봉현물데이터.xlsx`, `분봉현물데이터.xlsx`.
2. **B1/D1가 상한을 안 자름** — 과거 구간 요청해도 최근일까지 옴. **B1(시작)은 바닥으로 먹힘. 반드시 Python에서 날짜 필터.** 시각까지 넣어야(09:00~15:45) 정상.
3. 하루 봉수 ≈ 선물 84 / 현물 ~132(무체결봉 carry 포함).
4. **데이터 정제**: 무체결봉(체결거래량=0, 값 carry) + **이상치**(errant tick, 예 국고2년 저=2.869) → 저장 시 필터.

**수집 최적화 계획(합의)**:
- **저장**: 5분 4종목 백필 ≈ 60~100MB(2018~) → 로컬 SQLite 추천(헤드룸/속도). Supabase 무료도 5분이면 가능하나 1분/틱 가면 안 됨.
- **백필**: 99999/콜 페이지네이션(윈도우 뒤로) + 대기 + 날짜필터. 종목별 분봉 **이력 깊이 probe 먼저**(현물은 2026-01 확인, 선물 미확인).
- **증분**: 매일 **마지막 ts 이후만** insert. ★전체 재수집 금지.
- **원칙**: 일별 파이프라인이 매일 26년 재계산 → 아침 COM 에러의 원인. **인트라데이는 처음부터 증분으로**, 그 로직을 나중에 일별에도 역적용.
- 순서: (a)저장위치 확정 → (b)sandbox서 백필 페이지네이션+대기 → (c)증분 → 온보딩.

sandbox/에 탐색 스크립트 있음(작동하는 COM 분봉 패턴). 본 파이프라인 안 건드림.

**2026-08-04 완료 — 인트라데이 5분봉 백필+증분 구현·실검증·적재 ★DONE**:
- **저장(로컬 전용 확정)**: `db/intraday.sqlite` **별도 파일**, **wide `bars` 테이블**
  `(symbol, ts, open,high,low,close, volume, oi, fetched_at)` PK(symbol,ts).
  선물=가격/현물=수익률%. **volume**=선물 거래량/현물 체결거래량(액면). **oi**=선물 미결제(현물 NULL).
  ※체결거래대금(amount)은 지표연속에 IMDH 미산출(항상 0) → **컬럼 삭제**(config 현물 items도 7개로).
  일별 ledger(EAV·26년 full-recompute)와 물리 분리 → WAL·재계산 안 얽힘. **38.7MB**. Supabase 미러 안 함.
- **★IMDH 분봉의 진짜 동작(실측으로 이전 가설 정정)**:
  - **B1·D1(날짜창)이 전부 무시됨.** 오직 `조회건수(count)`만 유효 → **count개가 '오늘 기준 뒤로'** 온다.
    (검증: B1=07-25/2000, D1=오늘/2026-03/2025-06 다 넣어봐도 결과 동일 = 최근 count봉.)
    → **날짜 페이지네이션 불가.** 가용 전이력 = **count=99999 한 콜**. (이전 문서의 "B1 바닥먹힘/전진 페이지네이션"은 틀림.)
  - **가용 이력 깊이(99999 상한)**: 선물 C65/C67 **2021-07-26~**(99563봉/1229거래일), 현물 국고
    2년 2023-06-19(5035) / 3년 2023-06-23(21205) / 5년(18820) / 10년 25062. 각 콜 **15~17초**.
  - **무거운 콜을 한 앱으로 연달아 하면 Excel RPC 사망**(-2147023174) → **종목마다 프레시 Excel**(_open_app/_close_app 반복).
  - 대기: **A4(첫 데이터셀) 값 도착 폴링**(계산상태 아님 — IMDH는 비동기라 xlDone이어도 값 미도착). 15초 하트비트+에러(#NAME?)감지.
- **신규 코드**:
  - `config.py`: `INTRADAY_DB_PATH`·`INTRADAY_SYMBOLS`(6종목 항목·per·real=false)·`INTRADAY_CYCLE=5`·`INTRADAY_SESSION`(09:00~15:45)·`INTRADAY_BACKFILL_START`(저장 floor)·`INTRADAY_BACKFILL_COUNT=99999`·`INTRADAY_INCR_COUNT=3000`.
  - `intraday_store.py`: store.py 관례 계승(멱등 upsert, WAL). `last_ts(sym)`·`coverage()`.
  - `intraday_pull.py`: `_pull`(count봉 1콜)+`_ingest`(프레시앱·floor/증분필터·upsert). CLI **sync(기본)/probe/backfill**.
    `sync`=원클릭: 이력 없으면 99999 백필, 있으면 3000봉 증분(last_ts 이후만). 증분 count가 공백을 못 덮으면 자동 99999 승격. 세션필터·현물 무체결봉(vol=0) 드롭.
  - **`intraday.bat`**(루트): `python src\intraday_pull.py sync`. **run.bat과 완전 분리**(run.py는 intraday 무참조, DB 별도).
- **실검증 통과(2026-07-31 대조)**: 선물 O/H/L/close·OI **일별과 일치**(vol만 ~3%↓=마감동시호가분 5분봉 미포함, 설명됨). 현물 종가 3.751≈ECOS y_ktb3 3.758. 세션밖 0봉·중복 0·멱등 재실행 OK.
- **남은 폴티 = 현물 이상치 필터 (사용자 결정: 지금은 보류, 나중에)**: 국고2년에 **불가능 틱**
  (2025-02-17 수익률 20.0, 02-18 17.72) 2건 저장됨. 현재 무체결봉만 드롭, errant tick은 미필터.
  → 원데이터 보존 우선("급변은 살림" 철학과 일관). **Layer 2 조회 시점**에 보수적 절대범위(현물 close ∈ (0,12])
  또는 이웃대비 이상치로 걸러도 됨. 저장측에 넣으려면 `_parse`(intraday_pull)에 한 줄.
