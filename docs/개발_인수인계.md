## 1. 이 프로젝트가 뭔가
한국 국채선물(KTB 3년·10년) **트레이딩 에이전트**를 만드는 프로젝트.
- **Phase 0 (완료)**: 일별 42컬럼 데이터(`ktb_daily`)를 수집·검증·적재 → Supabase. 1999~현재 약 6,600 거래일.
- **Phase 2 (진행 중)**: 에이전트. **하이브리드 구조** = Layer 1(일별 두뇌: 방향·포지션) → Layer 2(분봉 실행: 진입·청산 타이밍).

## 2. 데이터 파이프라인 (매일)
사용자가 아침에 **인포맥스 로그인 → `run.bat` 더블클릭**. 내부:
```
[1/4] infomax_pull.refresh_all()  인포맥스 엑셀(infomax_data.xlsx) COM으로 새로고침
[2/4] infomax_pull.load()         엑셀 → ledger(sqlite) 적재
[3/4] update.main()               ECOS·FRED·FX 수집 + 파생계산 + CSV export + 건강리포트
[4/4] push_supabase.main()        out/ktb_daily.csv → Supabase(ktb_daily) upsert
```
원본 진실 = 로컬 `db/ktb.sqlite`(long ledger). wide `out/ktb_daily.csv`는 소비용. Supabase는 클라우드 미러(차장님 read-only).

## 4. ★ 인포맥스 IMDH 완전 가이드 (핵심)
인포맥스 데이터는 전부 Excel 애드인 함수 **IMDH**로 가져온다. API 아님.

### 함수 시그니처
```
=IMDH(구분, 종목코드, 조회항목범위, 시작일, 종료일, 조회건수, "옵션")
```
- **구분**: `STK`(국내주식) `IDX`(국내지수) `FUT`(국내선물) `OPT`(옵션) `FX`(외환) `IR`(금리) `BND`(채권) `ECO`(경제지표) `FRN`(해외지수) `FND`(펀드)
- **조회항목범위**: 헤더 셀 범위(예 `A3:B3`). 첫 칸=`일자`, 나머지=항목 텍스트.
- **조회건수**: 최대 **99999**. 길이가 넘으면 시작/종료일 옮겨 여러 번(페이지네이션). 공백 시작=종료일부터 N개.

### 실행 요건 (자동화 함정)
- **32bit Excel + 인포맥스 단말 로그인** 필수(데이터 피드).
- COM 자동화 시 XLL 애드인 수동 등록: `app.RegisterXLL(r"C:\Infomax\bin\excel\imxlexcelai.xll")` — `infomax_pull._register_addin(app)`가 처리.
- **`win32com.Dispatch`** 사용 (NOT `DispatchEx` — DispatchEx는 애드인 안 붙어 `#NAME?`).
- 좀비 Excel 정리: `_kill_headless_excel()` (창 없는 자동화 잔재만 종료, 사용자 Excel 보존).

### 우리가 쓰는 종목·항목 (실측 확정)
| 데이터 | 구분 | 코드 | 항목 |
|---|---|---|---|
| 3년 국채연결선물 | FUT | **C65** | 시가/고가/저가/현재가/전일대비/거래량/미결제약정수량/이론베이시스/외국인합·은행·투신·보험 매수수량·매도수량 |
| 10년 국채연결선물 | FUT | **C67** | (동일) |
| IRS 3년 / 10년 | IR | **IRSTP1KRW03Y** / **IRSTP1KRW10Y** | MID종가 |
| OIS 3년 (KOFR) | IR | **IRSKM5KRW03Y** | MID종가 |
| KOFR 금리 | ECO | **785831** | 현재가 |
- **연결선물**: 분기 월물을 자동 이어붙인 연속 시계열(롤 점프 있음 → `roll_flag`). C65/C67은 [1333] 선물›지수/금리›국채연결선물.
- **순매수 = 매수수량 − 매도수량**으로 계산 (인포맥스 '순매수수량' 컬럼은 투신 등 결측 있어 안 씀).
- settle는 '현재가'(종가) 사용 — 옛 '약정가/정산가'는 0 결측 많음.

### 옵션 문자열 (build_infomax.py가 조립)
```
Per=일        조회기준: 일(D)·분(MM)·틱(T)·주(W)·월(M)   ← 분봉은 Per=MM
Cycle=5       틱/분 주기 (분봉 5분이면 5)
Bizday=0      데이터 있는 일자만
sort=A|D      A=오름차순
real=false    조회순간 값 아님(확정치)
Quote=종가    종가/평균
Close=…       ★틱/분에서: 매수(bid)·매도(ask)·체결·이론가·현물가 선택 가능
Pos=20, Orient=V, DtFmt=1(YYYY-MM-DD), TmFmt=1(hh:mm:ss), unit=true
```
- **분봉 뽑기**: `Per=MM|Cycle=5` → 5분봉. `조회항목`에 시가,고가,저가,현재가,거래량. 히스토리 깊음(1999/2008~) → 초기 1회 페이지네이션(99999/콜, ~수십 콜), 이후 최근분만 증분.
- **호가·현물·이론가**: 틱/분에서 `Close=매수`/`매도`/`현물가`/`이론가` → 장중 스프레드·베이시스 계산 가능.

## 6. 데이터 규율
- **결측=빈칸(NULL)**, 0은 진짜 0. 다운스트림 0으로 채우지 말 것.

- 멱등: (date, field) 충돌 시 upsert. 몇 번 돌려도 동일.

### 8a. 인트라데이(분봉) 수집 — 탐색 완료, 구현 남음 ★현재 여기
**탐색 결과(sandbox/에서 검증)**: 선물·현물 5분봉 모두 **되고, 일별과 정합 확인**.

**분봉 IMDH 레시피** (일별과 옵션은 같고 Per/Cycle만 다름):
```
선물: =IMDH("FUT","C65",[일자,시간,시가,고가,저가,현재가,거래량,미결제약정수량],
            B1,D1,99999,"Per=MM,Cycle=5,sort=D,real=false,...,Pos=20,Orient=V,DtFmt=1,TmFmt=1")
현물: =IMDH("BND","KR1035G00003",[일자,시간,시가,고가,저가,현재가,체결거래량,체결거래대금],
            B1,D1,99999,"Per=분,Cycle=5,real=t,...")   ← 현물은 real=t
```
- **종목**: 선물 C65(3년)/C67(10년) 연결선물. 현물 **지표연속** `KR1035G00002/03/05/10`(2/3/5/10년) — 코드 안 바뀜.
- **항목**: 분봉은 **`시가/고가/저가/현재가`(플레인, 선물과 동일)**. 선물=가격, 현물=**수익률(%)**. `일자`+`시간`(별칼럼) → `ts`.
- **선물엔 미결제약정수량(OI)도 분봉으로 옴**(EOD 아님 — 이전 오판 정정). 현물엔 OI 없음, 대신 체결거래대금.
- **검증**: 07-31 5분봉→일 OHLC·OI가 우리 일별과 **정확 일치**(선물). 현물 5분 고/저=장외일별과 일치, y_ktb3(ECOS)와 일관.

**★ 분봉 gotchas (중요)**:
1. **계산에 시간 걸림 → 충분히 대기/폴링 후 읽기.** 고정 sleep 짧으면 **0봉/0값**(내가 여기서 헤맴). 작동 예: `_archive_discovery/5분봉현물데이터.xlsx`, `분봉현물데이터.xlsx`.
2. **B1/D1가 상한을 안 자름** — 과거 구간 요청해도 최근일까지 옴. **B1(시작)은 바닥으로 먹힘. 반드시 Python에서 날짜 필터.** 시각까지 넣어야(09:00~15:45) 정상.
3. 하루 봉수 ≈ 선물 84 / 현물 ~132(무체결봉 carry 포함).
4. **데이터 정제**: 무체결봉(체결거래량=0, 값 carry) + **이상치**(errant tick, 예 국고2년 저=2.869) → 저장 시 필터.

**수집 최적화 계획(합의)**:
- **저장**: 5분 4종목 백필 ≈ 60~100MB(2018~) → 로컬 SQLite 추천(헤드룸/속도). Supabase 무료도 5분이면 가능하나 1분/틱 가면 안 됨.
- **백필**: 99999/콜 페이지네이션(윈도우 뒤로) + 대기 + 날짜필터. 종목별 분봉 **이력 깊이 probe 먼저**(현물은 2026-01 확인, 선물 미확인).
- **증분**: 매일 **마지막 ts 이후만** insert. ★전체 재수집 금지.
- **원칙**: 일별 파이프라인이 매일 26년 재계산 → 아침 COM 에러의 원인. **인트라데이는 처음부터 증분으로**, 그 로직을 나중에 일별에도 역적용.
- 순서: (a)저장위치 확정 → (b)sandbox서 백필 페이지네이션+대기 → (c)증분 → 온보딩.

sandbox/에 탐색 스크립트 있음(작동하는 COM 분봉 패턴). 본 파이프라인 안 건드림.

- 캔들 색: 한국식 RED=상승, BLUE=하락.

## 10. 새 PC/집에서 셋업
```bash
git clone https://github.com/PHC-sys/KIS-Treasury-Agent
cd KIS-Treasury-Agent
pip install -r requirements.txt        # pandas 등 + pywin32(인포용)
# 환경변수 설정: ECOS_API_KEY, SUPABASE_DB_URL (User scope)
```
- **인포맥스 단말 있는 PC**: `python src\build_infomax.py`(워크북 재생성) → `run.bat`.
- **인포 없는 PC(개발만)**: 커밋된 `infomax_data.xlsx`로 충분 →
  `python src\infomax_pull.py load` (COM 불필요, openpyxl로 읽음) → `python src\update.py` (ECOS/FRED/FX 백필) → ledger·CSV 재구성. 또는 그냥 **Supabase에서 ktb_daily 읽어** 개발.
- 데이터만 필요하면 Supabase(`ktb_daily`)가 이미 최신 — 로컬 재구성 없이 바로 조회 가능.
